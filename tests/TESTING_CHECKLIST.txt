  ├── integration/                   # Integration tests (real workflows, may be skipped)
  │   ├── conftest.py
  │   ├── test_gui_interactions.py
  │   └── test_main.py
  ├── conftest.py                    # Root configuration
  └── TESTING_CHECKLIST.txt           # This file

UNIT TESTS: Test individual components in isolation using mocks. 
  Location: tests/unit/
  Run: ./run_unit_tests.sh
  Fast, no dependencies, safe for CI/CD

INTEGRATION TESTS: Test real workflows with actual components.
  Location: tests/integration/
  Run: ./run_integration_tests.sh
  May be skipped if marked with @pytest.mark.skip
  
RUN TESTS:
  - Unit tests only:        ./run_unit_tests.sh
  - Integration tests only: ./run_integration_tests.sh
  - All tests:              ./run_all_tests.sh
  - Specific folder:        pytest tests/unit/ or pytest tests/integration/

================================================================================
NOTES FOR TESTING
================================================================================

Organization Principles:
- Group tests by SYSTEM/COMPONENT, not by test type
- For each system, list UNIT tests first, then INTEGRATION tests
- This allows understanding all test coverage for a feature in one place
- Makes it easy to see what's fully tested vs partially tested

Unit Test Guidelines:
- Use pytest fixtures for setup/teardown
- Mock cloud API calls
- Mock GPIO for motor tests
- Mock SmartDot for sensor tests
- Use @patch decorators for isolation
- Location: tests/unit/
- Should run fast (< 1 second per test)

Integration Test Guidelines:
- Test real workflows with actual components
- Use real APIs (with test account) when possible
- NO @patch decorators (test actual behavior)
- Simulate real user interactions
- May be marked @pytest.mark.skip if not ready
- Location: tests/integration/
- Can be slower (allow up to 5 seconds per test)

GUI Testing:
- Use pytest-qt for PyQt6 UI tests
- Simulate user actions (clicks, key presses)
- Verify signal emissions
- Check widget state changes
- Test page navigation
- Verify dialog interactions

Code Coverage:
- Aim for >80% code coverage
- Priority: Business logic first (models, controllers)
- Then: API integrations
- Finally: GUI (visual inspection often sufficient)

CI/CD Integration:
- Run unit tests on every commit
- Run integration tests nightly or on demand
- Use separate test groups for speed
- Integration tests are allowed to take longer
- Generate coverage reports
- Fail the build on test failures

File Location Reference:
- Unit tests: tests/unit/<module_name>.py
- Integration tests: tests/integration/<feature_name>.py
- Configuration: tests/conftest.py (each directory)
- Documentation: tests/TESTING_CHECKLIST.txt

Running Tests:
  ./run_unit_tests.sh        # Fast, isolated tests
  ./run_integration_tests.sh # Real workflows
  ./run_all_tests.sh         # Complete suite
  pytest tests/unit/         # Run specific unit tests
  pytest tests/integration/  # Run specific integration tests
  pytest -v --tb=short      # Verbose with short tracebacks
  pytest -k "test_name"     # Run tests matching pattern
  pytest --cov=backend --cov=frontend --cov=utils  # Coverage report
